## Executive summary

- Fredman studies the length L of a longest increasing subsequence in a sequence of n distinct, linearly ordered elements. (PDF p. 1).
- The algorithm takes O(n log n) total time. Its worst-case comparison count is n log n − n log log n + O(n). (PDF p. 3).
- Fredman proves a matching worst-case comparison lower bound, up to an additive O(n) term. (PDF p. 7).

## Objectives

- Determine how much ordering information a comparison algorithm needs to compute L. (PDF p. 1).

## Arguments

- A comparison count gives a lower bound on total time. It does not by itself give a matching time upper bound, because additional computation can be necessary. (PDF p. 2).
- The lower-bound proof constructs k^(n−2k) orderings that must reach different leaves of a comparison tree. (PDF p. 7).

## Analysis

- T(k) stores the smallest final element of an increasing subsequence of length k in the processed prefix. This invariant establishes correctness. (PDF p. 2).
- The comparison upper bound is (n − L) log L + O(n). Its worst case occurs when L is approximately n/log n. (PDF p. 3).
- Lemma 3.6 equates the maximum L over linear extensions of a partial order with the minimum number of decreasing subsequences in a partition. (PDF p. 6).
- The comparison tree must have depth at least (n − 2k) log k. Choosing k = floor(n/log n) gives the stated lower bound. (PDF p. 7).

## Methods

- The algorithm, attributed to Knuth, maintains the first row of the Young tableau associated with the input sequence. (PDF p. 2).
- For each new element, compare it with the last occupied table entry. Append it if it is larger. Otherwise, replace the first table entry that is larger than it. (PDF p. 2).
- The occupied table entries remain increasing. Binary search finds the replacement position in O(log n) time. (PDF p. 3).

## Applications

- The same algorithm can answer whether L is at least k with at most n log k + O(n) comparisons. (PDF p. 6).

## Optimization

- Compare with the last occupied entry before binary search. Each extension of the table then needs only one comparison. (PDF p. 3).

## Evaluation and testing

- The evaluation uses worst-case comparison analysis and a binary comparison tree. Leaves represent partial orders implied by comparison outcomes. (PDF p. 3).

## Results

- The number of occupied table positions after all elements are processed equals L. (PDF p. 2).
- The upper and lower bounds determine the best worst-case comparison count to within O(n). Logarithms use base two. (PDF p. 2).

## Limitations and uncertainty

- The input model requires distinct elements from a linearly ordered set. (PDF p. 1).
- The lower bound applies to algorithms that compare input elements and branch on their relative order. (PDF p. 2).
