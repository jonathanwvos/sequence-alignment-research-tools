## Executive summary

- CREMSA compresses multiple sequence alignments by column runs and supports queries without full decompression. (PDF p. 2).
- The authors combine compressed bit vectors with sequence reordering to reduce storage and query time. (PDF p. 2).
- A 65 GB SARS-CoV-2 alignment becomes a 22 MB disk index that occupies 76 MB in main memory. (PDF p. 10).

## Objectives

- Support direct access and column statistics for large, highly redundant alignments. (PDF p. 2).
- Improve compression through sequence reordering and enable large-scale covariation analysis. (PDF p. 2).

## Arguments

- Column redundancy can remain high despite local sequence variation. The authors use this property to motivate column-based compression. (PDF p. 2).
- Both storage and statistical query costs depend on column run counts. Reducing these counts improves both costs. (PDF p. 5).
- The authors argue that BWT-based indexes do not directly provide counts across unrelated columns. CREMSA computes these counts by traversing runs. (PDF p. 9).

## Analysis

- With constant-time rank and select, access and run-length queries take constant time. Column counts take Θ(r_j), and pair counts take Θ(max{r_j1, r_j2}). (PDF p. 5).
- The authors use a reduction from Hamiltonian Path to establish the intractability of optimal sequence ordering for minimum total runs. (PDF p. 5).
- The implementation has different bounds. SD rank takes O(log(s/r_j)) and SD select takes O(1). RRR rank takes O(1) and RRR select takes O(log s). (PDF p. 6).

## Methods

- Store each column as a bit vector marking run starts and a string containing one symbol per run. Rank locates the symbol, and select locates run boundaries. (PDF p. 3).
- Implement the index in C++ with sdsl-lite v3. Use SD bit vectors when the run fraction is below 0.1 and RRR bit vectors otherwise. (PDF p. 6).
- Apply gzip to the stored index. Remove this gzip layer for queries while retaining the bit-vector compression. (PDF p. 6).
- Compute column entropy and pairwise G-test and RNAalifold scores to examine conservation and covariation. (PDF p. 8).

## Applications

- The index supports sequence recovery, nucleotide counts, column entropy, and statistics for pairs of alignment columns. (PDF p. 3).
- The authors apply it to 1,870,492 aligned SARS-CoV-2 genomes to investigate regions under evolutionary pressure. (PDF p. 8).

## Optimization

- Select d columns with the lowest identity fractions. Sort sequences lexicographically by the symbols extracted from those columns. (PDF p. 5).
- After column selection, bucket sorting takes Θ(sd) time and Θ(s) space. Rebuild the index one column at a time in the new sequence order. (PDF p. 5).
- The SARS-CoV-2 experiments use 5,000 selected columns. CREMSA compression rises from 965-fold in the initial order to 2,922-fold in this order. (PDF p. 6).

## Evaluation and testing

- Datasets include SARS-CoV-2, HIV-1, and MFS protein alignments. Artificial datasets use independent mutation, phylogenetic, and shuffled phylogenetic models. (PDF p. 3).
- Compression benchmarks compare CREMSA with gzip, xz, and CoMSA. They exclude sequence identifiers and use an Intel Xeon Gold 6130 system with 128 GB RAM. (PDF p. 6).
- Experiments use one thread except for CoMSA, which lacks a single-thread option. Reported times include user and system time. (PDF p. 6).
- COUNT tests select 500 columns in each of four run-count ranges and repeat each query ten times. A published Snakefile supports benchmark reproduction. (PDF p. 8).

## Results

- On the reordered 65 GB alignment, CREMSA takes 413 seconds and 529 MB construction memory. Including reordering raises these values to 859 seconds and 641 MB. (PDF p. 6).
- CoMSA achieves 5,285-fold compression with 66,429 MB memory. CREMSA achieves 2,922-fold compression, compared with 2,087-fold for xz. (PDF p. 6).
- Average nucleotide access time rises from 28 ns for 10,000 sequences to 111 ns for 1.87 million sequences. (PDF p. 8).
- Pair counts for about 607 million column pairs take five hours and 81 MB after reordering. The initial order takes 22 hours and 197 MB. (PDF p. 8).

## Limitations and uncertainty

- CREMSA does not store sequence identifiers. (PDF p. 6).
- Poor-quality genomes can introduce gaps and separate compensatory mutations across columns. The authors describe the biological findings as preliminary. (PDF p. 9).
- The authors propose further validation through phylogenetic subsampling and comparison with probing data. (PDF p. 9).
- Alignment construction remains a major cost. Halign3 required 1.2 TB RAM for the 1.9-million-genome alignment. (PDF p. 10).
