## Executive summary

- PipeMEM runs BWA-MEM in Spark through pipe operations. The authors use a pipeline for pre-processing and memory for main computation to reduce overhead. (PDF p. 1).
- The authors report average speedups of 2.27× over BWASpark and 2.33× over SparkBWA in multi-node alignment tests. (PDF p. 14).
- With pre-processing included, the reported speedup over SparkBWA ends at about 1.2×. (PDF p. 15).

## Objectives

- The authors aim to support BWA-MEM and future single-node alignment tools in a multi-node framework. (PDF p. 2).
- They aim to produce alignment results that existing genome analysis tools in a big data environment can use. (PDF p. 2).

## Arguments

- The authors argue that output files need no merge step. Later genome analysis steps require distributed data again. (PDF p. 3).
- They argue that JNI reduces portability and makes replacement of the alignment tool more difficult. (PDF p. 3).

## Analysis

- The authors define overhead as 1 − TBWA-MEM/Tframework. They state that this measure is meaningful only on one node. (PDF p. 9).
- They measure scale efficiency as T1 node/(P × TP node), where P is the node count. (PDF p. 9).
- The authors predict a maximum pre-processing speedup of 3× from the three-stage pipeline. (PDF p. 7).

## Methods

- Pre-processing changes the input format and uploads data to HDFS. Main computation distributes the data, restores the input format, calls BWA-MEM, and uploads results to HDFS. (PDF p. 3).
- PipeMEM uses standard streams and PipeRDD. It pipes RDD data through format conversion and BWA-MEM, then creates result RDDs for HDFS storage. (PDF p. 7).
- The authors state that the input format permits Spark to divide data while keeping each original data unit intact. (PDF p. 15).

## Applications

- PipeMEM supports alignment as the first step of a Spark genome analysis pipeline. Its distributed output is intended for the next analysis step. (PDF p. 3).
- The authors state that the framework can also run other single-node programs with map-pattern parallelism, including other alignment tools. (PDF p. 3).

## Optimization

- The pre-processing pipeline overlaps disk reads, CPU format conversion, and network uploads. Single-end input uses three processes. Paired-end input uses two readers, one converter, and one uploader. (PDF p. 6).
- Main computation keeps data in memory between HDFS input and output. This avoids local disk access before BWA-MEM. (PDF p. 7).
- Parameter tests on D1 selected four Spark tasks with eight BWA-MEM threads per task. (PDF p. 10).

## Evaluation and testing

- Tests used a 10-node cluster with a 1 GigE network. Each node had two eight-core E5-2670 CPUs and 64 GB memory. Software versions were Hadoop 2.6.4, Spark 2.1.0, and BWA 0.7.15. (PDF p. 9).
- The benchmark used subsets of NA12750 and NA12878. D2 contained 60 million read pairs of length 100 bp and occupied 31 GB. (PDF p. 9).
- Comparison settings were four tasks with eight threads for PipeMEM, 16 tasks for BWASpark, and two tasks with 16 threads for SparkBWA. SparkBWA used Spark-Join. (PDF p. 9).
- The authors compared total processing time on seven nodes because BWASpark had its best performance at that node count. (PDF p. 14).

## Results

- On D2, the pipeline reduced pre-processing time from 23.31 to 8.16 minutes. The reported speedup was 2.86×. (PDF p. 10).
- Across the reported node counts, PipeMEM was at least 2.2× faster than SparkBWA and at least 1.5× faster than BWASpark. (PDF p. 14).
- PipeMEM had longer pre-processing than SparkBWA but lower total processing time in the seven-node comparison. (PDF p. 14).
- The authors report about 20% higher overall speed than SparkBWA when pre-processing is included. (PDF p. 15).

## Limitations and uncertainty

- The D1 read-pair count is inconsistent. The prose gives 3.5 million pairs, but Table 2 gives 350,000 pairs. (PDF p. 9).
- Tests with more than eight tasks sometimes used swap memory. The authors did not present those results. (PDF p. 10).
- The authors state that pre-processing does not scale. Its cost reduces the overall speedup over SparkBWA. (PDF p. 15).
