## Executive summary

- The authors describe short-read mapping through hash tables, FM-indexes, and GPU implementations. (PDF p. 8).
- Their CPU comparison measures execution time and aligned reads with common input data and a single core. (PDF p. 9).

## Objectives

- Explain algorithm features and possible uses to support selection for short-read mapping. (PDF p. 2).

## Arguments

- The authors argue that algorithm selection must depend on experimental conditions, computing speed, and alignment accuracy. (PDF p. 10).

## Analysis

- FASTA selects k-tuple matches, scores candidate regions, and applies Smith–Waterman alignment. Its score threshold can exclude valid alignments. (PDF p. 3).
- MAQ hashes reads. Changes to the reads require a new hash table, and additional mismatches increase scanning time. (PDF p. 6).
- Bowtie uses a Burrows–Wheeler matrix, LF mapping, and greedy backtracking. The authors state that it does not always find the ideal alignment. (PDF p. 8).

## Methods

- BFAST builds reference indexes, applies masks to obtain spaced seeds, and identifies candidate alignment locations. It then applies Smith–Waterman local alignment. (PDF p. 5).
- SOAP uses seed extension and a hash lookup table. The described search allows one continuous gap or up to two mismatches. (PDF p. 6).
- RMAP divides a read into k + 1 adjacent seeds when k mismatches are allowed. It also uses quality scores to guide mapping. (PDF p. 6).
- GPU-RMAP transfers genome and read hash tables to GPU memory. It scans independent genome segments in parallel, scores locations, and distributes reads across threads to select the highest scores. (PDF p. 8).

## Applications

- The described algorithms map NGS short reads to reference sequences for DNA analysis and genome resequencing. (PDF p. 2).

## Optimization

- MAQ limits considered hits to at most two mismatches to increase alignment speed. (PDF p. 6).
- The authors suggest a binary search tree for GPU-RMAP lookup. Frequently accessed upper levels would use faster cache memory. (PDF p. 8).
- SOAP3 adapts the BWT-based SOAP2 method for GPUs and permits up to four mismatches. (PDF p. 8).

## Evaluation and testing

- The benchmark uses reference NZ_CP05032 and Illumina HiSeq 4000 reads from SRA SRR11461738. (PDF p. 9).
- All aligners run on one core of an Intel Xeon E5-2695 v4 at 2.10 GHz. Tests use zero mismatches, one mismatch, and default settings. (PDF p. 9).
- For RMAP, reads are padded with n bases to the maximum read length. The authors then adjust start and end positions to exclude padding when remeasuring accuracy. (PDF p. 9).

## Results

- The authors report that FM-index methods generally run faster and align more reads than hash-based methods in their comparison. (PDF p. 10).

## Limitations and uncertainty

- Few GPU tools were available for comparison. The performance analysis therefore focuses on CPU execution time and aligned reads. (PDF p. 9).
- Interpretation: aligned-read counts alone do not establish correct placement. The excerpt does not describe an independent truth set for the stated accuracy comparison. (PDF p. 9).
- The supplied table and figure captions do not provide numerical benchmark values. They do not support exact speedups or per-tool rankings. (PDF p. 9).
