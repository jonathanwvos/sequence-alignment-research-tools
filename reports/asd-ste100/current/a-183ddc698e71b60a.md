## Executive summary

- The authors develop data structures for shortest unique palindromic substring queries on run-length encoded strings. (PDF p. 1).
- The structures use O(m) space, where m is the number of runs. Two variants support query endpoints given as run indices and offsets. (PDF p. 3).

## Objectives

- Reduce SUPS storage requirements by making space depend on the encoded size rather than the full string length. (PDF p. 3).
- Support faster queries when the query interval is also specified in run-length encoded form. (PDF p. 3).

## Arguments

- The authors argue that earlier linear-space SUPS methods remain costly for large strings because their space depends on the uncompressed length. (PDF p. 3).
- Per-run endpoint lists contain O(log m) entries. Searching these lists permits faster queries than searching all endpoints together. (PDF p. 17).

## Analysis

- The space bounds count words in the word RAM model unless stated otherwise. (PDF p. 2).
- The proof uses O(log m) MUPS endpoints per run and O(m) endpoints in total. These bounds give O(m) total storage for the per-run search structures. (PDF p. 17).
- Binary search over O(log m) endpoints takes O(log log m) time. Reporting the answers adds an output term α. (PDF p. 17).

## Methods

- A SUPS occurs exactly once, contains the query interval, and has no shorter unique palindromic substring that contains that interval. (PDF p. 1).
- Preprocessing uses run-length encoded versions of Manacher's maximal palindrome algorithm and the eertree data structure. (PDF p. 3).
- Arrays mrb and mre store sorted MUPS beginning and ending positions for each run. Run-start positions convert query run indices and offsets into string coordinates in O(1) time. (PDF p. 16).
- Queries use successor searches on beginning positions and predecessor searches on ending positions to count contained MUPSs. Precomputed boundary answers handle runs without a suitable local endpoint. (PDF p. 17).

## Applications

- The authors cite molecular biology as motivation for SUPS queries. (PDF p. 3).

## Optimization

- The first encoded-query variant builds separate successor and predecessor structures for each run. (PDF p. 17).
- The second variant replaces these structures with binary search. It reduces construction time but gives slightly slower queries. (PDF p. 17).
- Simple scans construct the per-run endpoint lists and run-start positions in O(m) time. (PDF p. 16).

## Evaluation and testing

Not stated in the extractable source pages.

## Results

- Theorem 3 gives O(m log σRLE) construction time, O(m) space, and O(log log m + α) query time. Here σRLE is the number of distinct run characters and α is the number of reported SUPSs. (PDF p. 17).
- The authors present an RLE-based SUPS structure whose space is linear in the number of runs. (PDF p. 3).

## Limitations and uncertainty

- Some query intervals have no SUPS, so the output count α can be zero. (PDF p. 3).
- The faster query variants require query endpoints in run-length encoded form. (PDF p. 3).
