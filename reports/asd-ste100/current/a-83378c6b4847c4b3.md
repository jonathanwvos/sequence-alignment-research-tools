## Executive summary

- MMseqs2-GPU performs gapless filtering and gapped protein alignment on GPUs with position-specific scoring matrices. (PDF p. 1).
- The benchmarks show faster single-query searches and faster structure prediction workflows. Large-batch performance depends on GPU count. (PDF p. 2).

## Objectives

- Accelerate sensitive homology retrieval, query-centered MSA generation, and Foldseek structure searches without reducing sensitivity. (PDF p. 1).

## Arguments

- The authors argue that gapless filtering suits GPUs because it has few data dependencies and avoids the branching and random memory access of k-mer index searches. (PDF p. 5).

## Analysis

- The gapless recurrence is M[i,j] = max(M[i−1,j−1] + Q[i,sj], 0). Zero boundary values permit local alignment. The maximum matrix value gives the optimal gapless score. (PDF p. 5).
- A theoretical model gives an L40S peak of 23.2 TCUPS with half2 arithmetic. The measured synthetic peak of 13.5 TCUPS is 58% of that estimate. (PDF p. 7).
- The authors interpret this efficiency as evidence that shared-memory lookups and warp shuffles reduce memory overhead enough to make computation the main constraint. (PDF p. 7).

## Methods

- Each reference sequence is aligned against a query PSSM. The top k sequences that pass the inclusion threshold proceed to profile-based Smith–Waterman–Gotoh alignment on the GPU. (PDF p. 5).
- The gapped stage adapts CUDASW++4.0 to PSSMs and uses wavefront processing to satisfy dynamic programming dependencies. (PDF p. 1).
- The workflow transfers query profiles and reference batches from CPU RAM to the GPU. It sorts gapless scores, computes selected gapped alignments, and returns results to the CPU. (PDF p. 7).

## Applications

- ColabFold uses GPU homology searches to generate MSAs before AlphaFold2 model inference. (PDF p. 8).
- Foldseek applies the GPU search to protein structures represented as 3Di strings. Its benchmark searches 6,370 structures against 53.6 million entries. (PDF p. 9).

## Optimization

- The filter stores PSSMs in shared memory and reference residues in global memory at one byte per residue. It packs two 16-bit values into each 32-bit word. (PDF p. 5).
- Thread groups process separate alignments. Query segments contain up to 2,048 residues, and warp shuffles share diagonal values between threads. (PDF p. 2).
- Sorting reference sequences by length reduces unused GPU capacity caused by different sequence lengths. (PDF p. 7).
- Database partitioning and host-RAM streaming support databases that exceed GPU memory. Streaming retains about 63–65% of in-memory speed. (PDF p. 2).

## Evaluation and testing

- The sensitivity test uses 6,370 queries and 30,430,281 references, including 27 million reversed sequences. Same-family SCOP matches are true positives. Different-fold and reversed-sequence matches are false positives. (PDF p. 7).
- ROC1 measures recovery before the first false positive. Speed tests target comparable sensitivity and use query batches of 1, 10, 100, and 6,370. (PDF p. 8).
- Synthetic tests align one random query against five million equal-length random sequences. The base server has two 64-core AMD EPYC 7742 CPUs and 1 TB RAM. (PDF p. 7).
- Structure prediction tests use 20 CASP14 targets. Energy tests multiply sampled average power by runtime. Analysis scripts and benchmark data are available. (PDF p. 9).

## Results

- One L40S is 6.4 times faster than BLAST for single-query searches. For large batches, CPU k-mer search is 2.2 times faster than one GPU, but eight GPUs are 2.4 times faster than CPU k-mer search. (PDF p. 2).
- MMseqs2-GPU reaches ROC1 values of 0.400, 0.612, and 0.669 after one, two, and three iterations. These match the CPU gapless implementation. (PDF p. 8).
- GPU ColabFold is 1.65 times faster than CPU ColabFold and 31.8 times faster than the tested AlphaFold2 pipeline. All three obtain similar TM-scores of 0.70 ± 0.05. (PDF p. 3).
- Foldseek-GPU is 4 times faster than CPU k-mer Foldseek with one L40S and 27.3 times faster with eight. The authors also report small sensitivity gains. (PDF p. 3).

## Limitations and uncertainty

- The gapless filter does not provide the sensitivity-for-speed trade-off available in word-based methods. (PDF p. 3).
- The synthetic benchmark represents a best case because equal sequence lengths avoid variation in thread-group workloads. (PDF p. 7).
- JackHMMER timings and single-query DIAMOND timings use 10% of queries and extrapolation. The full 6,370-query JackHMMER batch was not run. (PDF p. 8).
- Cloud cost estimates depend on instance selection, region, and price date. The authors state that prices vary over time and between regions. (PDF p. 9).
