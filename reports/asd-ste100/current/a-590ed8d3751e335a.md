## Executive summary

- Accelign implements pairwise alignment on CUDA GPUs with a common DP wavefront design. It supports DNA, RNA, and protein sequences. (PDF p. 1).
- The library supports local, global, and semi-global score computation with linear or affine gaps. It does not compute detailed tracebacks. (PDF p. 3).
- The authors report peak global-alignment throughput of 16.1 TCUPS with linear gaps and 9.1 TCUPS with affine gaps on one RTX PRO 6000 Blackwell GPU. (PDF p. 1).

## Objectives

- The authors aim to generalize their GPU parallelization method across sequence types, scoring schemes, and alignment classes. (PDF p. 3).
- The library aims to support one-to-one, one-to-many, and all-to-all alignment on one or more GPUs. (PDF p. 3).

## Arguments

- The authors argue that substitution matrices and position-specific scoring require different memory-access strategies for efficient GPU execution. (PDF p. 3).
- The authors attribute high throughput to register computation, warp communication, and a reduced instruction count. (PDF p. 21).

## Analysis

- The peak-throughput model uses the number of streaming multiprocessors, instruction throughput, clock rate, and cycles per DP cell update. (PDF p. 20).
- The model gives 20.99 TCUPS for the tested Blackwell GPU. The measured 16.1 TCUPS corresponds to 77% of this peak. (PDF p. 21).
- PSSM benefits decrease for long queries because matrix tiling adds global-memory accesses that hide some lookup savings. (PDF p. 20).

## Methods

- Each alignment is assigned to a cooperative group of 4, 8, 16, or 32 threads. Groups process independent alignments while their threads compute one DP matrix along minor diagonals. (PDF p. 7).
- Warp shuffle instructions transfer values between thread registers and reduce memory traffic. (PDF p. 7).
- The high-level API selects a configuration from the maximum query length in a batch. Queries up to 512 use one tile; longer queries use multiple tiles of up to 1024. (PDF p. 18).
- The protein-search workflow first computes scores at reduced precision. It checks score validity and recomputes scores that are not certified exact with 32-bit arithmetic. (PDF p. 25).

## Applications

- Case studies cover DNA short-read alignment, protein database search, and HIV short-read mapping. (PDF p. 21).
- The HIV workflow scores both read orientations, selects the best passing orientation, and obtains alignment endpoints. Block Aligner then computes the corresponding tracebacks on the CPU. (PDF p. 27).

## Optimization

- The kernels use packed half2 arithmetic, architecture-specific min/max instructions, DPX instructions, and packed 8-bit arithmetic where supported. (PDF p. 7).
- A grid search selects GPU-specific tile sizes, thread configurations, and scoring-matrix configurations for alphabets of size 5 and 25. (PDF p. 18).
- Custom protein-search configurations adjust tile sizes to reduce computations outside valid sequence bounds. (PDF p. 25).
- For multi-GPU protein search, the reference database is divided so each GPU computes a similar number of DP cells. (PDF p. 25).

## Evaluation and testing

- Evaluation uses four systems with Blackwell, Ada, Ampere, and Hopper GPUs. The study includes synthetic throughput tests and real-world case studies. (PDF p. 18).
- The protein benchmark aligns 20 queries of lengths 144 to 5,478 against UniRef50 release 2025_03. It uses local affine alignment, BLOSUM62, gap-open −11, and gap-extension −1. (PDF p. 25).
- Protein-search comparisons include CUDASW++4.0 and BLASTP with 128 CPU threads. Database conversion and initial CPU-to-GPU database transfer are excluded. (PDF p. 25).
- The short-read benchmark uses a three-stage pipeline for input parsing, batch alignment, and score output. (PDF p. 21).

## Results

- For short DNA queries, PSSM lookup is up to 29% faster than substitution-matrix lookup with linear gaps. The reported gain is up to 16% with affine gaps. (PDF p. 20).
- The protein benchmark averages 6.44 TCUPS with the high-level API, 6.73 with custom settings, and 12.33 with 8-bit arithmetic. CUDASW++4.0 averages 6.38 and BLASTP averages 2.10 TCUPS. (PDF p. 25).
- Using two GPUs with custom settings increases protein-search performance by 88%–96% over one GPU. (PDF p. 25).
- The HIV workflow takes 0.5 seconds for GPU alignment and 0.2 seconds for CPU traceback, including transfers. BWA reports 0.78 seconds for its core processing and maps fewer reads. (PDF p. 27).

## Limitations and uncertainty

- Detailed traceback is unavailable. CPU traceback can become a bottleneck when many alignments require it. (PDF p. 28).
- The library does not detect unrepresentable values during reduced-precision computation. Wider score ranges require 32-bit types or applicable score-validity checks. (PDF p. 18).
- The library computes the full DP matrix. The authors expect methods that skip cells to be faster for some long-read workloads. (PDF p. 29).
- The configuration search covers only a subset of tile sizes. The best application performance can require custom tuning. (PDF p. 29).
