## Executive summary

- The authors give a RAM algorithm that computes LIS length k in O(n log log k) time for a permutation of n integers. (PDF p. 1).
- The algorithm reduces the priority queue key universe through repeated renaming. It also supports extraction of an LIS. (PDF p. 2).

## Objectives

- Express the running time in terms of output length k and improve the previous O(n log log n) bound. (PDF p. 2).

## Arguments

- The best final elements for successive subsequence lengths form an increasing sequence. This property supports efficient successor searches. (PDF p. 2).
- A key universe of size O(k) permits priority queue operations in O(log log k) amortized time. (PDF p. 2).

## Analysis

- With block size m at least k, radix sorting gives O(n) total renaming cost. Queue keys lie in {1, ..., 2m}, which gives O(n log log m) total time. (PDF p. 5).
- The algorithm tries block sizes with m_i = m_(i−1)^(log m_(i−1)). The authors bound the total cost of these trials by a geometric sum. (PDF p. 5).

## Methods

- Process elements in input order. Insert each element into the best-element queue and delete its successor if one exists. Otherwise, increase the current LIS length. (PDF p. 2).
- Store predecessor information with best elements. Follow these links backward to recover an LIS. (PDF p. 3).
- Split the input into consecutive blocks of size m. Keep both sorted and original block orders. (PDF p. 3).
- Stop a trial when the queue exceeds m elements. Increase m and repeat until the run completes. (PDF p. 5).

## Applications

- An LIS can select exact genome matches that occur in the same order in two sequences. The cited genome comparison approach requires each match to occur once in each sequence. (PDF p. 1).
- For a permutation S, its LIS is an LCS of S and the sequence (1, 2, ..., n). (PDF p. 1).

## Optimization

- Retain the core LIS algorithm and van Emde Boas queue. Reduce operation costs by renaming elements within each block. (PDF p. 3).

## Evaluation and testing

- A worked example processes 12 integers and ends with a queue of size four. Predecessor links recover the LIS (1, 2, 4, 5). (PDF p. 3).

## Results

- Theorem 2 states that both LIS length and an LIS can be computed in O(n log log k) time. (PDF p. 5).

## Limitations and uncertainty

- The authors leave the optimality of the bound open. (PDF p. 1).
- The authors describe the result as mainly theoretical. (PDF p. 2).
- The authors claim an extension to repeated integers by ranking pairs (value, position). My interpretation is that equal values then receive increasing ranks, so this reduction needs clarification for strictly increasing subsequences. (PDF p. 5).
