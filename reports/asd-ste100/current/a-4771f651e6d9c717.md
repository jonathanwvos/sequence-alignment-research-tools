## Executive summary

- The authors compute an LCS directly from run-length encoded strings. The final time bound depends on run counts rather than decoded lengths. (PDF p. 2).
- The initial algorithm takes O(kl(k + l)) time. It stores solutions for run-prefix pairs in a matrix of blocks. (PDF p. 3).
- The final algorithm uses balanced search trees to process forced paths in O(kl log(kl)) total time. (PDF p. 12).

## Objectives

- Find an LCS in time polynomial in the compressed input size. (PDF p. 2).
- Exploit repeated characters to improve on dynamic programming over all decoded character pairs. (PDF p. 2).

## Arguments

- Image rows and columns can contain few runs despite many pixels. The authors use this property to motivate direct matching of compressed strings. (PDF p. 2).
- The authors claim their algorithm is the first LCS algorithm with time polynomial in the sizes of both compressed strings. (PDF p. 2).

## Analysis

- For each dark block, the algorithm compares the upper and left prefix scores with forced-path scores obtained from two trees. (PDF p. 11).
- Ranks and values order the stored paths. Only the two relevant paths nearest the lower-right block corner need to be considered. (PDF p. 11).
- Each tree operation takes O(log(kl)) time. Since each deleted path was previously inserted, all deletions total O(kl). This gives the amortized time bound. (PDF p. 12).

## Methods

- The block matrix stores the optimum LCS value between prefixes ending at run boundaries. X has l runs and Y has k runs. (PDF p. 3).
- At a dark block, the method inserts a forced path with the upper-left prefix score. It deletes the new path or existing paths when score comparisons show dominance. (PDF p. 11).
- Tree queries find the best forced-path scores for the relevant row and column. The block value is the maximum of these scores and the two adjacent prefix values. (PDF p. 11).

## Applications

- The motivating OCR system compares binary rows or columns of query character images with character models. Typical lines contain about 50 pixels and only three or four color transitions. (PDF p. 2).
- The authors identify binary facsimile images as suitable for run-length encoding because they contain large regions of equal pixel values. (PDF p. 2).

## Optimization

- Balanced search trees replace evaluation of all relevant forced paths with ordered insertion, dominance deletion, and neighbor queries. (PDF p. 11).
- The analysis precomputes LEFT and TOP values in O(k + l) time before block processing. (PDF p. 12).

## Results

- Theorem 6 states O(kl log(k + l)) time for LCS computation on RLE strings. (PDF p. 11).
- The proof obtains O(kl log(kl)) time from processing kl blocks and amortizing tree deletions. (PDF p. 12).

## Limitations and uncertainty

- The algorithm relies on the LCS edit-cost setting. With unit insertion and deletion costs, substitution must cost at least two. (PDF p. 12).
- This cost condition permits horizontal or vertical transitions across light blocks. The authors state that this property does not hold for general edit costs. (PDF p. 12).
