## Executive summary

- MMseqs2 searches protein sequence sets through k-mer filtering, ungapped alignment, and vectorized Smith–Waterman alignment. (PDF p. 1).
- The supplement describes sequence and profile search modes, memory-access optimizations, and parallel execution. (PDF p. 3).
- The benchmark uses full-length proteins with SCOP-based annotations and reversed sequences to assess sensitivity and false matches. (PDF p. 4).

## Objectives

- Search and cluster large protein sequence sets with an improved sensitivity–speed tradeoff. (PDF p. 1).
- Build a sensitivity benchmark that includes disordered regions, membrane helices, and low-complexity regions that can cause false matches. (PDF p. 4).

## Arguments

- The authors argue that consecutive similar-k-mer matches on the same diagonal suppress chance matches while retaining homologous matches without intervening gaps. (PDF p. 1).
- The authors identify random main-memory access as a bottleneck for speed and multicore scaling. Their filtering design moves repeated diagonal checks into CPU cache. (PDF p. 2).
- The authors use structure-based evolutionary relationships as a benchmark standard because BLAST and SWIPE are themselves comparison tools. (PDF p. 4).

## Analysis

- The authors report that k-mer filtering removes 99.9% of targets and ungapped filtering removes a further 99%. About 10⁻⁵ of targets reach Smith–Waterman alignment. (PDF p. 1).
- Index entries require six bytes each, and target residues require one byte each. The stated memory requirement is 7NL bytes plus 8 × 21^k bytes for pointers. (PDF p. 2).
- Ungapped alignment has linear time complexity along a candidate diagonal. Smith–Waterman alignment has quadratic time complexity. (PDF p. 2).
- Target splitting reduces per-server memory but adds I/O-limited result merging. Query splitting avoids this target-merging cost. (PDF p. 4).

## Methods

- Generate similar query k-mers above a BLOSUM62 score threshold with branch and bound. Use the target index to detect consecutive matches on the same diagonal. (PDF p. 1).
- Compute optimal ungapped scores for 32 targets in parallel with AVX2. Pass alignments above 15 bits to vectorized Smith–Waterman alignment. (PDF p. 2).
- Apply local compositional bias correction in all three stages. Mask target low-complexity regions with TANTAN during k-mer and ungapped filtering. (PDF p. 3).
- Iterative search builds a query-centred star alignment from included matches. It filters at 90% pairwise identity, selects 100 diverse sequences, and adds sequence weights and pseudocounts. (PDF p. 3).

## Applications

- The suite supports protein sequence searching and clustering, including profile-to-sequence and sequence-to-profile searches. (PDF p. 1).
- Utility tools support format conversion, multiple sequence alignment, profile calculation, ORF extraction, six-frame translation, and result analysis. (PDF p. 4).

## Optimization

- Write seed matches sequentially, then bin them by low target-identifier bits. Process each bin with a diagonal array sized to fit CPU cache. (PDF p. 2).
- Store only the lowest eight bits of previous diagonal values to reduce the cache footprint. (PDF p. 2).
- Use AVX2 stripe-vectorized Smith–Waterman alignment. When filtering, calculate scores and selected endpoints without producing the full alignment. (PDF p. 3).
- Use OpenMP for independent query searches and MPI across servers. Select target or query splitting from available memory by default. (PDF p. 4).

## Evaluation and testing

- The benchmark starts with SCOP/ASTRAL 1.75 filtered to 25% pairwise identity. Matching to UniRef50 produces 6,370 full-length queries with 7,598 annotated domains. (PDF p. 4).
- Same-family SCOP matches are true positives. Reversed-sequence matches are false positives. The first benchmark also treats different-fold matches as false positives, except beta propellers. (PDF p. 4).
- Sensitivity is the fraction of true positives found before the first false positive, called AUC1. Overall FDR is the arithmetic mean of per-query FDR values. (PDF p. 4).
- Tests used two eight-core Xeon E5-2640v3 CPUs, 128 GB RAM, and a 30.4-million-sequence target database on local SSDs. Results were evaluated through rank 4,000 with an E-value limit of 10,000. (PDF p. 5).

## Results

- Building an index for 30 million sequences took 7.1 minutes on 16 cores. (PDF p. 2).
- The authors report that biased target regions caused false positives that could corrupt later iterative profiles. This observation motivated target masking. (PDF p. 3).

## Limitations and uncertainty

- The authors state that seed-stage sensitivity is critical because every target must pass through that stage. (PDF p. 1).
- The gapped alignment implementation accepts profiles against sequences but not the reverse orientation. Sequence-to-profile search therefore transposes candidate results before alignment and transposes them back afterward. (PDF p. 3).
- The benchmark ignores matches outside its specified true-positive and false-positive categories. (PDF p. 4).
- Runtime tests duplicated queries 100-fold. For SWIPE, BLAST, and RAPsearch2, the authors instead multiplied the original query-set runtime by 100. (PDF p. 5).
