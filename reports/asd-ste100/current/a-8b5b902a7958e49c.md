## Executive summary

- QuickEd first estimates an upper bound on edit distance. It then uses that bound to restrict DP computation and recover an optimal alignment. (PDF p. 2).
- The authors report strong performance on long, noisy sequences and memory use below 35 MB for sequences up to 1 Mbp with 10% error. (PDF p. 8).

## Objectives

- Combine fast heuristic score estimation with exact alignment to reduce time and memory requirements for long sequences. (PDF p. 3).

## Arguments

- The authors argue that an initial score bound can reduce the search needed for exact alignment. (PDF p. 2).
- They argue that reducing computed DP cells is insufficient when each cell requires substantial overhead or irregular computation. (PDF p. 2).

## Analysis

- The authors state O(n) time and O(1) memory for score approximation, and O(n ŝ) time for exact alignment. Here, ŝ is an upper bound on the optimal score. (PDF p. 2).
- Normalized Score Deviation measures average relative score overestimation. The authors also use it to indicate extra alignment work caused by a loose bound. (PDF p. 6).
- Larger windows improve score estimates but require more time. BandEd often gives tighter estimates, with substantially higher execution times on ONT data. (PDF p. 6).

## Methods

- QuickEd-Bound combines WindowEd with small and large windows and BandEd in a cascade to estimate the alignment score. (PDF p. 7).
- QuickEd-Align continuously uses the score bound to restrict the DP region while computing the optimal alignment. (PDF p. 3).
- Hirschberg division finds optimal breakpoints while storing one DP column. Small sub-alignments then use regular QuickEd-Align to recover the full alignment. (PDF p. 6).

## Applications

- QuickEd-Bound can provide rapid approximate alignment scores. Adding QuickEd-Align provides exact sequence alignment. (PDF p. 2).
- The authors present the library as a component for sequence analysis of long, noisy reads. (PDF p. 8).

## Optimization

- WindowEd uses a bit-parallel Myers kernel to compute larger windows efficiently and reduce memory use. (PDF p. 6).
- QuickEd organizes DP computation into 64 × 64 tiles and uses the score bound to avoid unnecessary tiles. (PDF p. 3).
- Hirschberg recursion reduces the memory needed for alignment recovery. (PDF p. 7).

## Evaluation and testing

- The C library was tested single-threaded on an Intel Xeon Platinum 8480+ at 3 GHz with 256 GB DRAM. Reproduction scripts are publicly available. (PDF p. 6).
- Simulated datasets used lengths of 10K, 100K, 500K, and 1M bases, with error rates of 1%, 5%, 10%, and 20%. Six real datasets covered Illumina, PacBio HiFi, and ONT reads. (PDF p. 6).
- Approximation tests compared score deviation and time against Scrooge, WindowEd, and BandEd. Exact tests compared time and memory against Edlib, KSW2, A*PA, A*PA2, WFA, and BiWFA. (PDF p. 6).
- Scrooge and A*PA2 tests replaced N with A because those tools accept only A, C, G, and T. (PDF p. 6).

## Results

- On long, noisy datasets, QuickEd was 4.2–5.9 times faster than Edlib and 3.8–4.4 times faster than BiWFA. (PDF p. 8).
- On ONT UltraLong, QuickEd took 835.2 seconds and used 33.7 MB. Edlib took 3,858.6 seconds and used 13.8 MB. (PDF p. 8).
- WFA-based implementations were 6.7–14.1 times faster than QuickEd on the high-quality Illumina and PacBio datasets. (PDF p. 7).
- In tests with N replaced by A, QuickEd achieved average performance ratios of 1.03 relative to A*PA2-simple and 0.94 relative to A*PA2-full. (PDF p. 8).

## Limitations and uncertainty

- The implementation supports only edit distance. (PDF p. 8).
- Window sizes, overlaps, and heuristic thresholds require parameter choices. Automatic parameter selection remains future work. (PDF p. 8).
- The minimum band spans 192 DP elements. This limits cutoff effectiveness for short, similar sequences. (PDF p. 7).
- QuickEd-Bound currently includes only WindowEd and BandEd. The authors propose adding other bounding and alignment algorithms. (PDF p. 8).
