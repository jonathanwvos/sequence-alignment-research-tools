## Executive summary

- The authors study jumbled indexing, borders, and squares on run-length encoded strings. Jumble matching requires equal symbol histograms. (PDF p. 2).
- The algorithms use the number of runs r as a complexity parameter. Border and square computation also depend on the decoded length n. (PDF p. 14).

## Objectives

- Build an index that returns all substrings whose histograms equal a query histogram. (PDF p. 3).
- For each prefix, compute its longest jumbled border and the longest jumbled square that ends at its final position. (PDF p. 3).

## Arguments

- The authors state that run-length input makes their methods particularly efficient when r is much smaller than n. (PDF p. 14).
- The authors explain that classical relationships between borders and periods do not carry over to the jumbled setting. (PDF p. 3).

## Analysis

- For square computation, each run in a potential start interval produces at most four windows of end positions. (PDF p. 13).
- The proof bounds the total windows for one ending run by O(r). Consecutive potential start intervals share at most two runs. (PDF p. 13).

## Methods

- The indexing construction represents symbol counts for each pair of endpoint runs as ranges. Symbols absent from both endpoint runs have fixed counts. (PDF p. 3).
- The square algorithm examines pairs of runs, computes potential start intervals, and produces windows of valid end positions. Rank and select queries support window calculations. (PDF p. 13).
- Separate union-find structures maintain windows for odd and even end positions. (PDF p. 13).

## Applications

- The authors cite jumbled pattern matching applications in mass spectrometry, alignment, SNP discovery, repeated pattern discovery, and metabolic network analysis. (PDF p. 2).

## Optimization

- Square windows arrive in decreasing square size. Each window updates only positions that have no previous answer. (PDF p. 13).
- The stated union-find method inserts O(r) windows in O(r) time for each ending run. (PDF p. 13).

## Evaluation and testing

Not stated in the extractable source pages.

## Results

- The index uses O(r²|Σ|) space and O(r²(log r + |Σ| log |Σ|)) construction time. Histogram queries take O(|Σ|³ log r) time. (PDF p. 14).
- Reporting all matches takes O(|Σ|³ log r + occ) time, where occ is the number of answers. (PDF p. 3).
- Both border and square computation take O(|Σ|(n + r²)) time and O(|Σ|n) space. (PDF p. 14).

## Limitations and uncertainty

- Interpretation: border and square processing does not use space bounded only by the compressed input size. Rank and select arrays and per-position answers require O(|Σ|n) space. (PDF p. 13).
- The authors leave further study of the case |Σ|r² = O(n²) as an open direction. (PDF p. 14).
