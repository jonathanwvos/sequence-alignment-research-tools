## Executive summary

- The authors compare LCS algorithms for two strings and multiple strings, with emphasis on time and memory requirements. (PDF p. 1).
- They describe memory allocation instrumentation and an extension of Wagner-Fischer to multiple input strings. (PDF p. 5).

## Objectives

- The authors aim to examine performance across input types, match-pair counts, and dominant-match counts. They identify memory use as a limiting factor for large inputs. (PDF p. 1).

## Arguments

- The authors argue that algorithm speed improvements depend on the input type. They attribute the weaker performance of finite automata for two strings to large overhead. (PDF p. 6).

## Analysis

- The review separates dynamic programming methods into row-by-row, contour-to-contour, and diagonal-wise procedures according to which table cells they process. (PDF p. 1).
- The authors state that contour methods perform well with large alphabets when dominant-match counts are close to match-pair counts. (PDF p. 2).
- The extended Wagner-Fischer implementation uses a memory block whose size equals the product of input-string lengths. Interpretation: this storage requirement grows rapidly as inputs are added. (PDF p. 5).

## Methods

- The extended Wagner-Fischer procedure iterates through a multidimensional table. Symbol comparisons use loops over the input strings. (PDF p. 5).
- A coordinate function maps each multidimensional index to linear memory. It repeatedly multiplies the accumulated index by the next sequence length and adds that coordinate. (PDF p. 5).

## Applications

- The authors identify file comparison, spelling correction, and comparison of DNA and protein sequences as LCS applications. (PDF p. 1).

## Optimization

- The authors replace the default C malloc and free functions to track memory consumption. They report using this instrumentation to find memory leaks and improve allocation. (PDF p. 5).
- The review describes diagonal extension through matching symbols and contour processing through dominant matches as ways to avoid unnecessary table work. (PDF p. 2).

## Evaluation and testing

- The stated evaluation plan includes input-dependent runtime, dominant matches, match pairs, and memory requirements. (PDF p. 1).
- The supplied implementation section describes allocation tracking but gives no measured memory totals or timing results. (PDF p. 5).

## Results

- The conclusion reports that fast dynamic programming methods outperform finite automata for two strings. The supplied conclusion gives no numerical comparison. (PDF p. 6).

## Limitations and uncertainty

- The authors report that they found no reference implementation against which to compare their multiple-input Wagner-Fischer extension. (PDF p. 5).
- Several complexity expressions in the supplied comparison table are incomplete or unreadable. These entries do not support reliable transcription of the stated bounds. (PDF p. 3).
