## Executive summary

- The authors parallelize LCS computation with multiple forbidden substrings. They use Wang et al.'s dynamic programming algorithm as the sequential basis. (PDF p. 2).
- Two BSP/CGM algorithms evaluate a task DAG with regular or irregular block partitions. Irregular partitions aim to reduce processor idle time. (PDF p. 2).

## Objectives

- The objective is to schedule dependent subproblems without redundant evaluation and obtain efficient parallel execution on p processors. (PDF p. 2).
- The second algorithm aims to keep processors active longer by fragmenting blocks in the task graph. (PDF p. 15).

## Arguments

- Equal block distribution balances assigned work, but DAG dependencies still leave processors idle. The authors use smaller blocks to expose more available work. (PDF p. 2).
- The authors attribute lower total execution time to reduced idle time and better load balance under irregular partitioning. (PDF p. 12).

## Analysis

- For regular partitioning, each processor evaluates p blocks. Each block takes O(nmr/p²) computation time, which gives O(nmr/p) time per processor. (PDF p. 7).
- For irregular partitioning, the computation bound sums decreasing block costs across fragmentation levels. The authors obtain O(nmr/p) time and O(kp) communication rounds. (PDF p. 10).

## Methods

- An Aho–Corasick automaton tracks constraint prefixes and detects forbidden substrings. Its transition table takes O(r|Σ|) time and space to construct sequentially. (PDF p. 3).
- The task DAG groups automaton-state subproblems at each input-position pair. Its edges represent the dependencies of the dynamic programming recurrence. (PDF p. 4).
- Algorithm A uses regular blocks and a snake-like processor assignment. It evaluates block diagonals in order and communicates dependency data after each diagonal. (PDF p. 7).
- Algorithm B fragments blocks and uses a snake-like assignment of small and large blocks. It also evaluates the resulting DAG by diagonals. (PDF p. 9).

## Applications

- The authors identify bioinformatics as an application area for LCS with multiple substring-exclusion constraints. (PDF p. 1).
- The experiments use real DNA and protein sequences, with alphabet sizes 4 and 20. (PDF p. 10).

## Optimization

- The sequential preprocessing removes duplicate constraints and proper superstrings of other forbidden constraints. These removals preserve the required exclusion conditions. (PDF p. 4).
- Parallel preprocessing assigns alphabet subsets to processors for transition-table computation. An all-to-all communication step then shares the results. (PDF p. 7).
- The fragmentation parameter k controls the irregular partition. Setting k = 0 reduces Algorithm B to Algorithm A. (PDF p. 10).

## Evaluation and testing

- The implementation uses C and OpenMPI on CentOS 7.6.1810. The cluster has dual Intel Xeon E5-2680 V4 processors per node and 100 Gbps Omni-Path links. (PDF p. 10).
- Tests vary sequence lengths from 768 to 4096, processor counts from 1 to 32, and k over 0, 1, and 2. They fix 20 constraints and vary total constraint length from 64 to 1024. (PDF p. 10).
- Speedup is single-processor time divided by parallel time. Efficiency is speedup divided by processor count. Reported communication time includes both data transfer and processor idle time. (PDF p. 10).

## Results

- Algorithm A has a reported O(nmr/p) execution time, O(p) communication rounds, and O(r|Σ|/p) preprocessing time. (PDF p. 7).
- Algorithm B retains O(nmr/p) execution time and O(r|Σ|/p) preprocessing time. Its communication-round bound is O(kp) for positive fragmentation counts. (PDF p. 10).
- For DNA inputs with n = m = 4096, r = 512, and 32 processors, execution time falls from 608.09 seconds at k = 0 to 429.57 seconds at k = 2. Speedup rises from 14.46 to 20.47. (PDF p. 12).
- For that configuration, efficiency rises from 45.18% at k = 0 to 63.96% at k = 2. (PDF p. 12).

## Limitations and uncertainty

- The irregular snake-like mapping balances block sizes but does not optimize communication. (PDF p. 9).
- The authors state that the best fragmentation count depends on input size and machine characteristics. (PDF p. 15).
- The reported experiments use at most 32 processors and fix the constraint count at 20. These settings limit the direct experimental evidence for broader scaling. (PDF p. 10).
